# Taste
- When presented with a reviewed list of issues/improvements, wants the full set addressed in one pass — including lower-severity ("medium") items — rather than only the single high-priority fix. Confidence: 0.6
- Deploys front-end projects to Netlify by running the build locally and dragging the `dist` folder into Netlify, rather than relying on a git-connected CI build. Confidence: 0.5
- Before committing to multi-step implementation work, asks for an explicit checklist/plan to review first ("give me the checklist first"). Confidence: 0.6
- Wants the agent to proactively identify what it can complete without user input ("which things can you do right now without my help?") and start on that set, while clearly separating work it can do autonomously from items genuinely blocked on the user's decisions/content. Confidence: 0.5
- Asks blunt "is this 100%?" / "is it good enough?" questions (e.g. "is the current website good enough for marketing now?") and expects a candid verdict with concrete gaps, tradeoffs, and flagged risks — not reassurance or a summary of what's already fine. Confidence: 0.7
- Targets international clients and does not want to be positioned as a local/Bangladesh-based (cheap-market) provider; avoid local-market / NAP / local-business signals and position for global reach instead. Confidence: 0.6
- Gives terse, high-level prompts and lets the agent do the investigation, choose the idiomatic approach, and decide/confirm the design itself; expects the agent to keep going through long-running steps on its own. Confidence: 0.5
- Wants user-facing copy proofread for grammar/spelling: when flagging one wording error, expects the agent to sweep and fix the other grammatical mistakes in the same copy, then report exactly what changed. Confidence: 0.6
- Asks clarifying questions about ambiguous terminology or data-field meaning (e.g. "what does year mean?") instead of assuming. Confidence: 0.4
- Avoids login/auth infrastructure: prefers the simplest working setup and relies on obscurity (unguessable admin/dashboard URLs, noindex, robots.txt disallow) rather than adding sign-in/sign-up, even accepting the trade-off of publicly writable data. Confidence: 0.6
- Optimizes for the lowest-effort/lowest-cost option that still works and defers non-blocking polish (e.g. keeping a personal Gmail address as the contact address instead of setting up a domain mailbox), asking "will it be a huge problem?" before investing in the proper setup. Confidence: 0.5
- Readily greenlights ("yeah, do it" / "yeah fix that") the small optional improvements the agent proactively offers — copy, polish, or technical/SEO fixes — so it is welcome to keep proposing them. Confidence: 0.6
- Delegates version-control operations to the agent ("push to github for me"), i.e. is comfortable having the agent stage, commit, and push to the repo (GitHub remote, `main` branch) on their behalf rather than running git manually. Confidence: 0.5
- Wants all site/brand copy written in plural team voice ("we", "our", "Who Are We?") — never first-person singular — so clients believe multiple people are working on it, even when the user is doing the work solo. Text that is the client's or visitor's own voice (testimonials, FAQ questions, prefilled enquiry messages) must stay "I". Confidence: 0.85
